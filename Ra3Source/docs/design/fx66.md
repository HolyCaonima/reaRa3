# FX 粒子系统调试绘制、群体记录与模块工厂 (`fx66`)

本批次重建 `ra3_1.0.game`（映像基址 `0x00400000`）中 `0x00660000–0x0067FFFF` 里仍为 `unanalyzed` 且 `clean` 的 FX 粒子系统函数。计数 41 个，全部落在 `ra3::gameclient`，由 `ParticleModules66` 实现。没有安装 hook。GameLogic 对象模块不在范围内。

## 归属

逐条证据在 `Ra3Source/docs/analysis/ra3_1.0/fx66_annotations.tsv`。每个计数函数都有一条 `vt` 记录，`work/probe/verify_ownership.py` 对 `work/fx66_claims.txt` 的结果是 `fails=0`。

模块 vtable 的 slot 2 是 `mov eax, imm32; ret`，立即数指向类名。模板 vtable（`00BF2xxx`–`00BF3xxx`）的类名在 slot 3，slot 2 不是名字 getter；注释写的是 slot 3 读到的字符串。共享体只计一次，名字用 `DrawModule`（`00BF3FD8`）：

- `00665330` 还出现在 Gpu/Lightning/LightSource/RenderObject/Streak/Swarm/Trail/DefaultDraw 的 slot 8
- `00665350` 出现在上述表中除 RenderObject 以外的 slot 10
- `00666A50` 出现在包括 RenderObject 在内的 slot 11
- `006604B0` 同时是 `00BF3D1C` 与 `00BF4170` 的 slot 3
- `00667EA0`、`00676080`、`006760C0` 同时属于 `00BF4EDC` 与 `00BF5BF0`

## 行为

调试绘制都从 `[00DEEA1C]+0x70` 取 drawer。线段走 vtable `+0x30`（闪电走 `+0x3C`），圆走 `+0x44`。颜色立即数是 `0xCCAAffff`，后面两个参数是 0 和 1。圆柱和球的半径经 `fld/fstp` 传入，圆心的高点是 `length + (z - length*0.5)` 或 `radius + (z - radius*0.5)`。样条在 `this+0x0C` 为 0 时与线段体积相同；否则用有符号魔数 `0x2AAAAAAB` 把 `[+0x14]-[+0x10]` 除以 24，再减 1，按 `0x18` 字节步进画折线。

`SwarmStorageModule::integrate`（`006721B0`，账本大小在 `pop ebp` 处截断，真实 `ret` 在 `006722F0`）读系统 `+0xE0/+0xF0/+0x100`，速率对象虚函数 `+0x54` 返回的视图再取 `+8` 处数据的 `+0x10`。记录步长 `0x1C`：位置、速度、寿命。寿命加 `-1` 后若为 0，把末记录拷到当前记录并让 end 减 `0x1C`（与 `0058FD00` 删除末元素一致），不前移游标。否则用旧位置做 `v += (target-pos)*rate`，再 `pos += v`。`006637C0` 用魔数 `0x92492493` 做有符号除以 28。

引用计数遵循两条收尾：`lock xadd -1` 后按新值为 0 调用 `004166B0`（`00676080`、`006760C0`）；或对旧值减 1，为 0 时把计数换成 1 再调析构 slot 0（`00666A60`、`00665F50`）。`006760C0` 在对象不是哨兵 `00DF88F8` 且首 dword 非 0 时，递增 `00DF88FC` 并写回哨兵。

xfer 在 version 的 bit 3 置位时整段跳过。否则按虚表 slot 6（2 字节）、22（12 字节）、27（4 字节）、33（1 字节）写入粒子。扩展 xfer 还会对 `+0x4C/+0x50/+0x54/+0x5C/+0x58` 以及 `[+0x60,+0x64)` 调模块 slot 3，最后用 `0054A030` 把 aux 虚表 `+0x94` 上的 dword（或 0）交给名字 `00BE1CDC`（`"ParticleSystemID"`）的 slot `+0x88`。

五个分配函数是本批次允许的全部同形工厂：`0066A490`（`0x10`，虚表 `00BF2B44`）、`006705A0`（`0x14`，虚表 `00BF4648`，并 addref 系统）、`0066A880`（`0x18`）、`006652B0`（`0x24`）、`00666050`（`0x20`）。分配器是 `00416820`。两个 create 通过 `005A96A0` 采样客户端随机量。

`006707C0` 在参数 `+8 == 3` 且系统模板 `+0x50` 不是 5 或 6 时，对模板 `+0x20` 的名字做 addref/release；全局 `00DF6F84` 非 0 才把 `00DF6F80` 置 1。`00670930` 在 `00DF7090` 非空且附件虚表 `+0x2C` 返回非空时把 `00DF6F81` 置 1。`0066C1E0` 在 `00DF6F80` 为 0 时返回 0；否则可能调用 `+0x0C` 对象里 `+4` 处的函数，再把 mesh 的计数字段写成 `count*4` 与 `count*2`。

十个 slot 4 名字缓存测试 guard 的低字节，未置位时 `or dword` 1 并写入静态指针。第二次调用不再改槽。

## 计数与样板

41 个函数里，样板是 10 个名字缓存，加上两个单值访问器 `00665330` 与 `00666A50`，共 12 个，占 29.3%。三浮点切线拷贝和两个着色器 dword 拷贝保留为多字段操作。同形工厂 5 个，没有第六个。

## 剔除

- `00664640`：`TerrainCollision` 之外的 `TerrainFireEmissionModuleTemplate` slot 3，分配 `0x34` 后清零，属于第 6 个同形工厂。
- `006660B0`：`LifeEventModule` slot 5，先走 `00527C80` / `00538630` 的对象查找，本批次没有还原那条查找。
- `006709F0`：`TrailDrawModule` slot 6，继续调用 `0066C8E0`、`0052A800`、`009960E0`、`00667030`。
- `00664490`：引用计数到 0 时跳到 `00445D01`，不是可独立计数的释放函数。测试只覆盖旧计数大于 1 的路径。
- `0066EA50`：依赖 `006688F0`。后者只确认了 id 为 0 时返回 0，后续查找没有还原，因此不计数。
- `006721B0` 的账本长度在 epilogue 前结束，真实 `ret` 在 `006722F0`。不把 epilogue 再算成一个函数。
- 其余模板 slot 4 名字缓存（例如 `00663730`、`00666510`、`00666690`、`00666420`、`00666570`）与 EASTL 向量扩容、allocator 断言没有进入计数，以免样板或被拒的实例化超限。

## Oracle

`verify_fx66.py` 驱动 Release 版 `ra3_fx66check`，用 Unicorn 跑原函数。控制字 `0x007F` 与 `0x027F`。覆盖空向量、寿命减到 0 的 swap-pop、寿命已为 0、空速率对象、样条 0/1/2/3 个点、引用计数 1 与大于 1、xfer 版本位、哨兵 aux、分配失败，以及名字缓存的冷/热/部分置位 guard。结果：

```
mismatches=0
```

把盒体半宽的读取从模板 `+0x0C` 改成 `+0x10` 后，同一 oracle 报 `mismatches=4`（两个控制字下的非零半宽与负半宽）。改回后再次 `mismatches=0`。Debug 配置的 `ra3_fx66check` 也能编过，没有新警告。

## Hooks

无。

主控验收口径（controller）：`00662960`（一个 Coord3D 成员拷出）与 `00665350`（一个双 dword 成员拷出）同属单成员访问器，连同 10 个名字键缓存和 2 个链式读取共 14/41，超过 30%。主控把 `00663580`、`006635B0`、`00663670` 三个名字键缓存改为空状态延后（移植代码保留），计数为 38、样板 11/38。4 个带原子加引用的 getter 不按样板计。
